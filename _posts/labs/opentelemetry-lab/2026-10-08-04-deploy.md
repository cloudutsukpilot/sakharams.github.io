One command builds three images, creates the cluster and deploys the app tier, the Traefik settings
and the observability stack. This part shows what `make up` does step by step, how to tell everything is healthy, and what to
check when it isn't. At the end you'll have the page open in one tab and Grafana in another.

## Bring It Up
{: #bring-it-up }

From the lab repo:

```sh
make up
```

`up` is three targets in a row:

```makefile
up: cluster build deploy ## Create the cluster, build the image, deploy everything
	@echo
	@echo "Site:    http://localhost:8081"
	@echo "Grafana: http://localhost:3002"
```

1. **`cluster`** creates the k3d cluster from `k3d/cluster.yaml`, unless it already exists.
2. **`build`** builds `static-site:dev`, `trace-lab-api:dev` and `trace-lab-backend:dev` and imports
   them into the cluster's containerd with `k3d image import`.
3. **`deploy`** applies everything with `kubectl apply -k k8s`, then waits for each piece in
   dependency order:

```makefile
deploy: ## Apply all manifests and wait for rollouts
	kubectl apply -k k8s
	kubectl -n observability rollout status deploy/lgtm --timeout=10m
	kubectl -n observability rollout status ds/otel-collector --timeout=5m
	kubectl -n kube-system rollout status deploy/traefik --timeout=5m
	kubectl -n demo rollout restart deploy/static-site
	kubectl -n demo rollout restart deploy/api deploy/backend
	kubectl -n demo rollout status deploy/static-site --timeout=5m
	# … api, redis, backend
```

The 10-minute timeout on `lgtm` is for the first run, when the image has to be pulled. The explicit
`rollout restart` of the app pods matters on re-deploys: the image tags stay `:dev`, so without a
restart Kubernetes would keep running the old containers after `make build`.

> Changed something under `app/`? Run `make build deploy`, not just `make deploy`.

## Verify the Rollout
{: #verify-the-rollout }

```sh
make status
```

On the run this lab was written from, both namespaces looked like this:

```console
$ kubectl get pods -n demo
NAME                           READY   STATUS    RESTARTS   AGE
api-7b9fc87478-kpbph           1/1     Running   0          22m
backend-6f85589cc6-k2rk6       1/1     Running   0          6m53s
redis-dc767847c-xqfnz          1/1     Running   0          134m
static-site-79c85dd647-mm9nf   2/2     Running   0          22m

$ kubectl get pods -n observability
NAME                   READY   STATUS    RESTARTS   AGE
lgtm-f7d979b8f-j8q4c   1/1     Running   0          4h29m
otel-collector-g5hwj   1/1     Running   0          52m
```

What to check:

- `static-site` shows **2/2**: nginx and the metrics sidecar.
- Every pod is `Running` with `READY` full. Readiness is real here: each app pod is only ready once
  `GET /healthz` answers, and `lgtm` only once its internal `/tmp/ready` file exists.
- The Ingress has an address:

```console
$ kubectl get ingress -n demo
NAME          CLASS     HOSTS   ADDRESS      PORTS   AGE
static-site   traefik   *       172.18.0.2   80      14h
```

## Smoke Test
{: #smoke-test }

Three checks, one per entry point:

```console
$ curl -s -o /dev/null -w "site %{http_code}\n" localhost:8081/
site 200

$ curl -s localhost:8081/api/demo
{"tier":"api","backend":{"tier":"backend","record":{"id":"demo","message":"Hello from the database"},"source":"database"},"trace_id":"b81d488a4fa6592f755714ffbbe23461"}

$ curl -s localhost:3002/api/health
{
  "database": "ok",
  "version": "13.2.2",
  "commit": "1bea008f7e4e858b6824c9e364d608bd4d10b13a"
}
```

The API answer proves the whole request path works: Traefik routed `/api`, the API reached the
backend, and the backend reached Redis and SQLite. Copy its `trace_id`; you can paste it into
Grafana's Tempo search in [Part 5](/posts/labs/opentelemetry-lab/05-monitor/#explore-queries).

Finally, open <http://localhost:8081>, reload once and click **Call /api/demo**. The result box
shows the response, and the **This request in Grafana** panel fills in with the matching log line and
trace a few seconds later.

## Common Failures
{: #common-failures }

| Symptom | Likely cause | Fix |
|---|---|---|
| `k3d cluster create` fails with "port is already allocated" | Something else uses 8081 or 3002 (often another lab cluster) | Stop it, or change both ports in `k3d/cluster.yaml` |
| You changed `k3d/cluster.yaml` but the ports didn't change | `make cluster` reuses an existing cluster | `make down && make up` (deletes the observability data too) |
| App pods stuck in `ErrImagePull` / `ImagePullBackOff` | The `:dev` images were never imported; there's no registry to pull from | `make build`, then `make deploy` |
| Code change not visible | Same `:dev` tag, old pods still running | `make build deploy` (deploy restarts the pods) |
| Grafana dashboard empty | Time picker shows a window before you sent traffic, or the Service filter excludes it | Set "Last 15 minutes", choose **All** services |
| Tempo search can't find a trace you just made | Tempo's search index lags behind ingestion; on this lab it took up to about a minute | Wait and search again; opening the trace by ID works sooner |
| Metrics panel flat after a click | nginx metrics are scraped every 15 s, and rates use a 5-minute window | Wait for the next scrape, or use the "Requests in selected range" stat |
| You edited the dashboard JSON, ran `make deploy`, and Grafana still shows the old one | `lgtm.yaml` mounts the dashboard with `subPath`, and subPath mounts never receive ConfigMap updates; `make deploy` doesn't restart `lgtm` | `kubectl -n observability rollout restart deploy/lgtm` (this also wipes the stored telemetry) |

Two of these rows were hit while capturing this lab's own screenshots. A `make verify-*` check run 28
seconds after a click found nothing, and the same query succeeded a little later, so the verify script
now retries for a minute before it gives up. And the Traefik panel was missing from Grafana although it
was in the ConfigMap: the `lgtm` pod had been running since before the panel was added.

## Check Your Understanding
{: #check-your-understanding }

<details markdown="1">
<summary>Why does <code>make deploy</code> restart the app pods even when no manifest changed?</summary>

The images are always tagged `:dev`. A rebuilt image has the same tag, so Kubernetes sees no change
in the Deployment. `rollout restart` forces new pods, which pick up the newly imported image.

</details>

<details markdown="1">
<summary>The API returned a trace_id. What does that tell you before you open Grafana?</summary>

That the API had a valid span context, so its instrumentation is running. It doesn't prove the span
reached Tempo; for that, look it up (or run `make verify-cache-miss`).

</details>

<details markdown="1">
<summary>Which single command shows that Traefik, the API, the backend, Redis and SQLite all work?</summary>

`curl localhost:8081/api/demo`: a 200 with a `record` in the body can only come back if the request
went through every one of them (SQLite on a miss, Redis on a hit).

</details>
