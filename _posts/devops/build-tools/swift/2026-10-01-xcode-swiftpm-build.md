Swift projects are built either with **Swift Package Manager** (packages, server-side Swift,
libraries) or with **Xcode / `xcodebuild`** (iOS, macOS, watchOS and visionOS apps). App builds add
steps other languages do not have: code signing with certificates and provisioning profiles,
archiving, and exporting an `.ipa` for TestFlight or the App Store. fastlane automates most of it.

## At a glance

| Category | Common tools |
|---|---|
| Build tools | Xcode, `xcodebuild`, Swift Package Manager (`swift build`), Tuist / XcodeGen (project generation), fastlane |
| Package managers | Swift Package Manager, CocoaPods (maintenance mode), Carthage |
| Build files | `Package.swift`, `Package.resolved`, `*.xcodeproj`, `*.xcworkspace`, `*.xcconfig`, `Info.plist`, `*.entitlements`, `ExportOptions.plist`, `Podfile`, `Fastfile`, `Appfile`, `Matchfile` |
| Lint and format | SwiftLint, SwiftFormat |
| SAST (open source) | MobSF / mobsfscan, Semgrep, CodeQL (Swift) |
| SAST (commercial) | NowSecure, Checkmarx One, Veracode, Snyk Code, SonarQube Server |
| SCA | Snyk, Mend, OSV-Scanner (`Package.resolved`), GitHub dependency graph |
| Frameworks | SwiftUI, UIKit, Combine, SwiftData; server-side: Vapor |
| Test and coverage | XCTest, Swift Testing, XCUITest; Xcode code coverage (`xccov`), Slather |
| Build output | `.app`, `.xcarchive`, `.ipa`; `.xcframework` for libraries |
| CI cache | SwiftPM `.build/` and `SourcePackages`, DerivedData, `Pods/` |

## How the build works

In CI, each stage of the [generic build pipeline](/posts/devops/build-tools/language-build-ecosystem/#generic-pipeline) maps to a Xcode command, plugin or scanner. Press play, or step through it:

{% include flow-anim.html id="devops/build-tools/swift/xcode-ci-pipeline" %}

- **Schemes** choose which targets to build, test and archive; mark them *Shared* so they are
  committed and visible to `xcodebuild` in CI.
- **Build settings** come from the project file and `.xcconfig` files; keep environment-specific
  values (bundle ID, API URLs) in `.xcconfig` rather than editing the project in CI.
- **Signing** needs a distribution certificate and a provisioning profile on the build machine.
  fastlane `match` stores them encrypted in a git repo or cloud bucket and installs them in CI.
- **macOS runners are required** for iOS builds; they are slower and more expensive than Linux, so
  cache aggressively and run lint/SAST on Linux where possible.

## Build files

| File | Purpose | Commit? |
|---|---|---|
| `Package.swift` | SwiftPM manifest: products, targets, dependencies | Yes |
| `Package.resolved` | Locked package versions | Yes |
| `*.xcodeproj`, `*.xcworkspace` | Xcode project / workspace (or generated by Tuist/XcodeGen) | Yes (or the generator spec) |
| `xcshareddata/xcschemes/*.xcscheme` | Shared schemes used by CI | Yes |
| `*.xcconfig` | Build settings per configuration | Yes, without secrets |
| `Info.plist`, `*.entitlements` | App metadata and capabilities | Yes |
| `ExportOptions.plist` | Export method (app-store, ad-hoc), team ID, signing | Yes |
| `Podfile`, `Podfile.lock` | CocoaPods dependencies (legacy projects) | Yes |
| `fastlane/Fastfile`, `Appfile`, `Matchfile` | Automation lanes and signing config | Yes |
| `*.p12`, `*.mobileprovision`, App Store Connect API keys | Signing material | Never in plain text |
| `DerivedData/`, `.build/`, `build/` | Build outputs | No |

## Commands by category

```bash
swift build -c release                           # build a Swift package
xcodebuild -resolvePackageDependencies -scheme Demo   # resolve packages
swiftlint --strict                               # lint
mobsfscan --json -o mobsf.json Sources/          # SAST (MobSF static rules)
xcodebuild test -scheme Demo -destination 'platform=iOS Simulator,name=iPhone 16' -enableCodeCoverage YES -resultBundlePath TestResults.xcresult   # tests + coverage
xcrun xccov view --report TestResults.xcresult   # coverage report
xcodebuild archive -scheme Demo -configuration Release -archivePath build/Demo.xcarchive   # archive
xcodebuild -exportArchive -archivePath build/Demo.xcarchive -exportOptionsPlist ExportOptions.plist -exportPath build/   # export .ipa
fastlane beta                                    # build + upload to TestFlight (lane below)
```

## Minimal project

```swift
// swift-tools-version: 6.0
// Package.swift
import PackageDescription

let package = Package(
    name: "Demo",
    platforms: [.iOS(.v17), .macOS(.v14)],
    products: [.library(name: "Demo", targets: ["Demo"])],
    dependencies: [
        .package(url: "https://github.com/apple/swift-log.git", from: "1.6.0")
    ],
    targets: [
        .target(name: "Demo", dependencies: [.product(name: "Logging", package: "swift-log")]),
        .testTarget(name: "DemoTests", dependencies: ["Demo"])
    ]
)
```

```ruby
# fastlane/Fastfile
default_platform(:ios)

platform :ios do
  lane :beta do
    setup_ci
    match(type: "appstore", readonly: true)
    build_app(scheme: "Demo", export_method: "app-store")
    upload_to_testflight(skip_waiting_for_build_processing: true)
  end
end
```

## CI with GitHub Actions

{% raw %}
```yaml
name: ios-ci
on: [push, pull_request]
permissions:
  contents: read

jobs:
  test:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/cache@v4
        with:
          path: ~/Library/Developer/Xcode/DerivedData/**/SourcePackages
          key: spm-${{ hashFiles('**/Package.resolved') }}

      - run: brew install swiftlint
      - run: swiftlint --strict
      - run: |
          xcodebuild test -scheme Demo \
            -destination 'platform=iOS Simulator,name=iPhone 16' \
            -enableCodeCoverage YES -resultBundlePath TestResults.xcresult

  beta:
    if: github.ref == 'refs/heads/main'
    needs: test
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - run: bundle install && bundle exec fastlane beta
        env:
          MATCH_PASSWORD: ${{ secrets.MATCH_PASSWORD }}
          MATCH_GIT_BASIC_AUTHORIZATION: ${{ secrets.MATCH_GIT_BASIC_AUTHORIZATION }}
          APP_STORE_CONNECT_API_KEY_KEY: ${{ secrets.ASC_API_KEY }}
```
{% endraw %}

Simulator names change with each Xcode release on hosted runners. Check the runner image's
installed simulators (`xcrun simctl list devices`) or select the Xcode version explicitly.

## Best practices

- **Prefer Swift Package Manager** for new dependencies; CocoaPods is no longer actively developed.
- **Commit `Package.resolved` and shared schemes** so CI resolves and builds the same thing as
  Xcode.
- **Manage signing with fastlane `match`** (or Xcode Cloud) and an App Store Connect API key;
  never commit `.p12` files or passwords.
- **Generate the project** with Tuist or XcodeGen on large teams to avoid `.pbxproj` merge conflicts.
- **Split jobs**: lint and SAST on cheap Linux runners, build/test/archive on macOS.
- **Increment build numbers in CI** (`agvtool` or fastlane `increment_build_number`) so every
  upload is unique.
