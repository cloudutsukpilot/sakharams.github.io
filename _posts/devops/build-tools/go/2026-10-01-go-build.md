Go ships its build system inside the language toolchain: `go build`, `go test`, `go vet` and Go
modules cover what other languages need three or four tools for. DevOps work in Go is mostly about
reproducibility, static binaries, vulnerability checks and packaging releases for many platforms.

## At a glance

| Category | Common tools |
|---|---|
| Build tools | `go build`, `go install`; orchestration with Make / Task / Mage; releases with GoReleaser; images with ko; Bazel (`rules_go`) for monorepos |
| Package registry | Go modules via `proxy.golang.org`, checksum database `sum.golang.org`, private `GOPROXY` (Artifactory, Athens) |
| Build files | `go.mod`, `go.sum`, `go.work`, `Makefile`, `.goreleaser.yaml`, `.golangci.yml`, `.ko.yaml` |
| Lint and format | `gofmt`, `go vet`, staticcheck, golangci-lint |
| SAST (open source) | gosec, Semgrep, CodeQL, SonarQube Community Build |
| SAST (commercial) | Checkmarx One, Veracode, Snyk Code, SonarQube Server |
| SCA | govulncheck (call-graph aware), OSV-Scanner, Trivy, Grype, Snyk, Mend |
| Frameworks | `net/http`, Gin, Echo, chi, Fiber, gRPC-Go, Cobra (CLIs) |
| Test and coverage | `go test`, testify, gomock, `go test -cover`, `go tool cover` |
| Build output | Static binary per OS/arch, archives and checksums (GoReleaser), OCI images (ko) |
| CI cache | `~/go/pkg/mod` (module cache), `~/.cache/go-build` (build cache) |

## How the build works

In CI, each stage of the [generic build pipeline](/posts/devops/build-tools/language-build-ecosystem/#generic-pipeline) maps to a Go toolchain command, plugin or scanner. Press play, or step through it:

{% include flow-anim.html id="devops/build-tools/go/go-ci-pipeline" %}

- **Minimal version selection** picks the lowest version that satisfies every requirement, so
  builds are reproducible without a separate lockfile; `go.sum` stores the checksums.
- **The build cache** makes repeated builds and tests fast; cache it in CI.
- **`CGO_ENABLED=0`** produces a fully static binary that runs in `scratch` or distroless images.
- **Cross-compiling** is built in: `GOOS=linux GOARCH=arm64 go build ./cmd/app`.

## Build files

| File | Purpose | Commit? |
|---|---|---|
| `go.mod` | Module path, Go version, `toolchain` line, requirements | Yes |
| `go.sum` | Checksums of every module version used | Yes |
| `go.work` | Local multi-module workspace | Usually no (developer convenience) |
| `vendor/` | Vendored dependencies (`go mod vendor`) | Optional, for air-gapped builds |
| `Makefile` / `Taskfile.yml` | Standard targets: build, lint, test, release | Yes |
| `.goreleaser.yaml` | Cross-platform builds, archives, checksums, SBOMs, images | Yes |
| `.golangci.yml` | Enabled linters and settings | Yes |
| `.ko.yaml` | Base image and build settings for ko | Yes |

## Commands by category

```bash
go mod download && go mod verify                 # fetch and verify modules
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w -X main.version=1.0.0" -o bin/app ./cmd/app   # build
go vet ./... && golangci-lint run                # lint
gosec ./...                                      # SAST
govulncheck ./...                                # SCA (only vulnerable code you actually call)
go test -race -coverprofile=cover.out ./...      # tests + coverage
go tool cover -func=cover.out                    # coverage summary
cyclonedx-gomod app -json -output sbom.json ./cmd/app   # SBOM
goreleaser release --snapshot --clean            # multi-platform release locally
```

## Minimal project

```text
// go.mod
module github.com/example/demo

go 1.24

require github.com/go-chi/chi/v5 v5.2.0
```

```makefile
# Makefile (recipes must be indented with tabs)
VERSION ?= $(shell git describe --tags --always)

.PHONY: build lint test vuln
build:
	CGO_ENABLED=0 go build -trimpath -ldflags="-s -w -X main.version=$(VERSION)" -o bin/app ./cmd/app
lint:
	golangci-lint run
test:
	go test -race -cover ./...
vuln:
	govulncheck ./...
```

## CI with GitHub Actions

{% raw %}
```yaml
name: go-ci
on: [push, pull_request]
permissions:
  contents: read

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version-file: go.mod              # caches module + build cache automatically

      - run: go mod verify
      - run: test -z "$(gofmt -l .)"           # fail on unformatted files
      - run: go vet ./...
      - run: go run honnef.co/go/tools/cmd/staticcheck@latest ./...
      - run: go run github.com/securego/gosec/v2/cmd/gosec@latest ./...
      - run: go run golang.org/x/vuln/cmd/govulncheck@latest ./...
      - run: go test -race -coverprofile=cover.out ./...
      - run: CGO_ENABLED=0 go build -trimpath -ldflags="-s -w -X main.version=${{ github.sha }}" -o bin/app ./cmd/app

      - uses: actions/upload-artifact@v4
        with:
          name: app
          path: bin/app
```
{% endraw %}

Pin tool versions (`staticcheck@2025.1`, `gosec@v2.22.0`) instead of `@latest` once the pipeline is
stable, so a new linter release cannot break unrelated builds.

## Best practices

- **Commit `go.sum`** and run `go mod verify`; use `go mod tidy -diff` in CI to catch an untidy
  `go.mod`.
- **Set `GOFLAGS=-mod=readonly`** so builds never silently modify `go.mod`.
- **Use `GOPRIVATE` and a private `GOPROXY`** for internal modules instead of committing tokens.
- **Build static, stripped binaries** (`CGO_ENABLED=0`, `-trimpath`, `-ldflags="-s -w"`) and
  inject the version with `-X`.
- **Prefer govulncheck as the gate**: it reports only vulnerabilities in code paths you call, so it
  has far fewer false positives than manifest-only scanners.
- **Release with GoReleaser** to get archives, checksums, SBOMs and signed images from one config.
